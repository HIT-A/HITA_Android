## 三、改动边界

133 个文件，按域分组：

### 1. 提醒（纯新增 + 一处契约变更）

| 文件 | 说明 |
|---|---|
| `data/work/ReminderRuleSet.kt` | 规则模型。**契约变更**：新增 `endLeads`（下课前提前量），提醒去重键从 `event#lead` 改为 `event#phase#lead` |
| `data/work/ExamReminderWorker.kt` | 考试提醒，固定四档 24h/12h/1h/30m（对齐 iOS `fixedExamReminderDates`） |
| `data/work/ExamReminderScheduler.kt` | 考试提醒自调度链 |
| `ui/settings/CourseReminderSettingsActivity.kt` | 提醒设置页（课前 `[0,5,10,15,30]`、下课前 `[0,5,10]`） |
| `data/work/CourseReminderWorker.kt` | 按下课前/上课前分流发通知 |

**去重键变更是有意的**：同一门课「课前 5 分钟」与「下课前 5 分钟」是两个提醒，只带 `lead` 会互相遮蔽。已发提醒存在 `SharedPreferences` 里，升级后旧键失效一次，最多重复一条通知。

### 2. 课表可恢复删除

| 文件 | 说明 |
|---|---|
| `data/model/timetable/EventEditHistoryEntity.kt` | 编辑历史表（Room v19） |
| `data/source/dao/EventEditHistoryDao.kt` | 历史读写 |
| `data/repository/EventEditHistoryStore.kt` | 软隐藏/物理删除分流 + 回放 |
| `data/repository/SnapshotRetention.kt` | 快照保留策略（`MAX_LIMIT = 40`） |
| `data/repository/TimetableSnapshotStore.kt` | 保留上限持久化到 `SharedPreferences` |

语义：教务导入/跟读/培养方案的课软隐藏（`hidden = 1`），手动课物理删除，**两者都写历史行，均可 `restore(historyId)` 回放**。删除与历史写入包在同一 Room 事务里。

**Room 版本从 18 升到 19**。`app/schemas/.../19.json` 是导出的 schema，必须随代码提交。

## 四、这个分支改了两处构建配置

**review 时请重点确认这两处**：

```gradle
// app/build.gradle
multiDexEnabled true      // 新增
```

原因：项目类数已超过单 dex 上限，未声明 multidex 时 D8 会把 `HApplication` 排到非主 dex，**安装后启动即 `ClassNotFoundException`**。这是既有问题（`main` 也有），只是之前没人在模拟器上冷启动验证过。

```gradle
testImplementation(libs.orgJson)   // 新增
```

原因：JVM 单测里 Android 的 `org.json` 是桩实现，`JSONObject` 一律抛异常。测试依赖里换成真实实现，纯函数解析器才能在 JVM 上验证。

## 八、常见陷阱

- **`app/schemas/.../19.json` 必须提交**。Room 导出的 schema 是迁移测试的输入，漏提交会让 `AppDatabaseMigrationChainTest` 在别人的机器上失败。
- **kapt 偶发 `processingEnv must not be null`**。这是 kapt 自身竞态，不是代码错误。遇到就 `./gradlew --stop` 后加 `--rerun-tasks` 重跑。
- **模拟器 `-gpu` 参数与 AVD 的 `hw.gpu.enabled=no` 冲突会让进程秒退**。用默认 AVD 配置启动即可，不要额外传 `-gpu off`。
- **校园四页 `exported=false`**，`adb shell am start` 会被拒。要验证请走 instrumentation，不要改 manifest 的 `exported`。
- **不要为了「统一」把课程的「刚到期立即发」改成考试的「已错过不补发」**，两者是刻意的差异，代码里有注释说明。
