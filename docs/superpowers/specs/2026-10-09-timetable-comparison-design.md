# HITA 课表主页入口与双人课表对比设计

日期：2026-10-09。分支：`feat/timetable-sharing`。实现基线：`3846021`。
状态：Tasks 1–6 已完成，逐任务及整功能独立 Review 已结束，发现的测试夹具问题已修复并复审。全量 JVM 测试、Debug 与 AndroidTest 编译通过；设备运行验收未执行。用户已授权主代理完成后 commit 并 push origin/feat/timetable-sharing；2026-10-10 已撤销关机要求。

## 1. 用户目标及已确认规则

用户认为分享功能藏在个人课表详情中不便使用，要求将分享、生成口令、查看/保存好友课表入口移到课表主页，并计算共同空闲和课程冲突，在原有课表 UI 上显示。

最新要求：按节次匹配，午休与课间不算共同空闲；仅相同节次结构的用户可对照。默认每天 08:30–22:30，可调整，但只纳入完整落在该范围内的节次，不截出半节。共同空闲是同一节次双方均无课程，冲突是同一节次双方均有课程占用。选择自己的一份课表与一位已保存好友，沿用主页面的周次导航。完整课表与仅忙闲课表均支持。结果仅作展示，不加入自己的课程、日程或提醒。

本轮范围为双人比较，不包含多人、活动/考试占用、联网同步、分享协议升级或新增数据库表。这里只判断课程安排，界面明确使用“共同无课时间”解释结果，不能承诺没有其他个人安排。

## 2. 已核实的现有基础

- `MainActivity.kt` 的课表工具栏已有课表名选择、壁纸、显示设置及添加事件操作，空间有限。
- `TimetableFragment.kt` 是主课表视图，承载周次导航及课程编辑；`TimetableWeekContent` 在相同时间坐标中绘制网格与课程层。
- 主课表当前可能聚合多份个人课表。对比须明确指定一份个人课表，不能隐式把所有显示事件当作比较输入。
- `TimetableShareActivity` / `TimetableShareViewModel` 已支持个人课表选择、昵称、模式、生成口令、复制和系统分享；可以直接复用。
- `FriendTimetableActivity` 已提供好友列表和导入流程；`FriendTimetableRepository` 提供独立表的观察、预览、确认保存、备注、删除。
- 分享快照保存实际安排起止时间、有效期及 Asia/Shanghai 时区；个人 `EventItem` 也保存每次实际时间。无需从星期/节次推导单双周。
- 个人 `scheduleStructure` 与分享快照 `periods` 已保存每项作息的起止分钟。本仓库默认结构有六项，分别为08:30–10:15、10:30–12:15、14:00–15:45、16:00–17:45、18:45–20:30、20:45–22:30；本轮以每项为一个比较节次，不自动拆成45分钟小节或猜测项内课间。
- 数据库当前版本 15，分享协议为 HITA1。本轮无需改变两者。

## 3. 课表主页入口

在主课表工具栏增加带无障碍说明的“分享与好友”操作，打开底部操作面板，提供“分享课表 / 生成口令”“导入口令”“好友课表”“课表对比”四项。工具栏空间不足时，将壁纸与显示设置收纳为设置菜单，保留添加事件操作，避免挤压课表名称。

分享直接打开现有分享页，默认选择当前明确选择的课表；主页面尚未明确选择或选择失效时，由分享页展示课表选择，不猜测后自动生成。导入口令直接进入已有好友页面的导入状态；仅在用户确认后保存，不自动读取剪贴板。好友课表进入独立列表，允许查看、备注及删除。

现有个人详情中的 ICS 导出保留；已有分享快捷入口可保留为辅助入口，但主页是首要入口。好友管理入口统一复用已有模块，不复制保存逻辑。

## 4. 开启与退出对比

“课表对比”打开配置面板，选择一份个人课表和一位好友，默认时间为 08:30–22:30。日范围使用同一天内的开始/结束时间，要求开始小于结束；本轮不提供跨夜范围。仅选择被范围完整包含的节次，没有完整节次时提示调整范围。提供共同空闲和冲突的显示开关，默认都开启。没有个人课表或好友时，显示创建/导入引导，不进入无意义的对比状态。

选择对象后检查节次结构：项数、顺序和每项起止分钟必须完全一致，不能只看节次编号、学校或校区相同。有效结构须非空、起止合法、有序、不重叠。不兼容时提示“节次结构不同，无法对照”，列出双方作息供查看，禁止开启比较，不默认换算或强制修改作息。分享、导入与独立查看好友课表仍可正常使用。

开启后主课表显示“正在对比：我的课表 × 好友备注/昵称”状态条、颜色及文字图例、调整和退出操作。当前比较对象由明确 ID 标识，不能使用列表下标。对比期间课程层仅展示被选中的个人课表课程，其他个人课表及个人活动暂不绘制；明确提示“仅比较所选课表课程”。退出后恢复原主课表聚合显示与编辑交互。

对比模式下网格点击不新增事件，长按不编辑；自己的课程点击可查看详情，比较区域点击查看时间。退出对比恢复既有操作，避免把对比误操作成课程编辑。

周次切换沿用主课表导航；计算跟随实际显示周的日期，不用双方第 N 周直接相配。状态以 SavedStateHandle 保存所选 ID、时间范围和显示开关，旋转与重建后恢复并重新读取数据。退出清除启用状态；不修改普通课表的显示偏好。

## 5. 时间与判定规则

所有比较日期和坐标显式采用校园时区 Asia/Shanghai；手机系统时区变化不得移动比较结果。周起点为校园时区周一零点。

先比较双方作息的完整有序起止分钟列表，完全相同才计算。没有结构、无效结构或不兼容均不得用默认结构代替；不以选定范围内部分节次相同放行。

每份课表有效期按照现有数据的实际时间边界 `[startMillis, endMillis)` 使用，不自行将结束时间扩展到次日。按校园日期生成完整节次，只有整个节次同时位于双方有效期内才可判定。部分节次超出共同有效期时，整节为未知，不标为空闲，也不截出半节；全部节次未知时提示不在双方共同有效期内。无需学期名称相同，只看日期。

个人输入仅取选定 timetableId 的 CLASS 事件，包括正式手动课程；好友输入取已校验的完整快照或忙闲占用。读取失败、缺失、非法时间或无效有效期均报错，不能退化为“没有课程”。有效个人课表确实没有 CLASS 记录时，该有效期内课程占用为空，允许计算共同无课时间；不要使用会拒绝空课表的分享生成方法完成比较。

课程和节次均使用半开区间 `[start, end)`，占用条件为 `course.start < period.end && course.end > period.start`：

1. 课程与一个节次有任何正时长重叠，该节对该用户即为有课；跨多个节次分别占用。端点相接不算占用。
2. 同节双方均无课 → 共同空闲；双方均有课 → 同节有课冲突；仅一方有课 → 非共同空闲且非双方冲突；未知 → 不判定。
3. 判定输出完整节次，而非两门课的精确交集。即使自己08:30–09:00、好友09:30–10:00实际不重叠，只要都占08:30–10:15这一节，仍为同节有课冲突。详情明确解释该语义，不称其为实际时间重叠。
4. 两个节次间的空档不生成空闲；相邻空闲节次也按独立节次保留，不合并跨过休息时间。
5. 记录重复不会重复统计节次。处于作息之外的课程仍按原始时间展示，并提示“作息外课程未参与节次对照”，不为其创造新节次。

例如默认结构双方上午两节都有课，则10:15–10:30课间及12:15–14:00午休均不显示为共同空闲；双方第三节均无课时只标14:00–15:45。若某门课09:00–10:00占用第一节，该节剩余时间不再标空闲。

每日汇总显示共同空闲节次数和同节冲突节次数，附完整节次时长合计；不能把合計称为精确课程重叠时长。未知、单方有课及作息间空档不计入这两类。

## 6. 在原有课表上显示

为原周课表增加独立的比较绘制层，与课程共享日期、时间到坐标的转换、缩放和滚动；不把空闲或冲突伪装成 EventItem。这样不会被原课程重叠分组误处理，也不会进入个人事件数据流。

- 共同空闲用绿色半透明底色及“共同空闲”标签，置于课程层下方。
- 冲突用红色边框/纹理及“同节有课”标识，覆盖完整节次，避免不透明遮住课程名称。
- 图例同时使用颜色与文字，不仅依赖红绿辨识；绘制层提供可访问的节次摘要。每日列表逐节展示，不能合并跨过课间。
- 点击显示校园日期、节次编号、该节起止时间和时长；冲突涉及自己的课程及好友 FULL 课程时可列名称和实际上课时间，说明“双方该节都有课，未必实际时间重叠”。好友 BUSY 只显示占用，不显示或推断名称与地点。
- 默认时间轴须覆盖选择范围和当前周所选个人课程；不修改用户普通课表时间轴偏好。对比模式不启用添加课程的网格点击。

现有“同一人的多门课程重叠”冲突卡与本功能的“双方课程冲突”必须用不同文字说明，计算不能复用其同人冲突语义。

## 7. 数据流与隔离

新增纯 Kotlin 节次比较模块，输入为双方完整作息、有效期、实际占用及显示周/范围，输出逐日逐节状态和统计；不依赖 Android/Room/Compose，不写数据。实际时间只用于判断是否占节次和绘制课程。

Repository 在后台读取选定个人课表和其 CLASS 事件的一致数据，以及好友快照。ViewModel 持有配置与加载/成功/失败状态，结合当前周、个人变化及好友变化重新计算。共享既有 friend DAO 观察接口；只有必要时增加按课表的数据观察接口，不改变原全局事件查询语义。

配置变更或切周时取消旧任务，并以所选 ID、窗口及请求序号校验结果，防止旧结果覆盖新周。加载或错误时隐藏旧比较区域并显示状态。好友更新、修改备注或删除，以及个人课表删除/更新，均重新确认当前对象及完整作息结构；更新导致结构不兼容时停止计算并提示，保留配置供调整，不显示旧比较结果。删除对象后停止比较并提示，不继续显示缓存结果。

好友数据与比较结果只进入比较 ViewModel/绘制层；不写个人 timetable、subject、events，不增加提醒任务。分享生成仍保持现有持久 shareId；进入比较不创建分享身份，不生成新口令。

## 8. 验证与验收

纯 JVM 自动化覆盖：完全相同作息、同项数但时间不同、同范围但拆节方式不同、无效/空结构；午休和课间无结果；半节占用使整节有课；实际不重叠但同节均占用仍冲突；相接端点、重复与嵌套记录、跨午夜/跨周、单双周实际日期、调课、部分未知节次、空个人课程、非法记录、无共同有效期、FULL/BUSY 等价占用、08:30–22:30 范围及整节过滤、作息外课程提示。

状态及投影测试覆盖：切周/换好友旧结果失效、对象删除停止比较、更新重新计算/不兼容停用、退出恢复普通显示、忙闲隐私、完整节次坐标和逐节详情、实际日期对应及不生成个人事件写入操作。数据隔离需要实际调用 Repository/数据库路径的有意义检查，不能仅比较计算对象。

执行 JVM 测试、Debug APK 构建、AndroidTest 编译和仓库检查。设备可用时验证主页四入口、剪贴板与分享菜单、旋转状态恢复、校园时区、原课表缩放/滚动、覆盖层点击与文字对比度、退出恢复编辑，以及好友更新/删除后的实时刷新。没有设备时明确区分编译通过与运行验收。

验收流程：课表主页生成口令 → 同页导入并保存好友 → 选定相同节次结构的双方课表开启对比 → 08:30–22:30 内逐节查看绿色共同空闲及红色同节有课，午休和课间不着色 → 切周结果随实际日期改变 → 更新好友后检查兼容性并重算 → 退出恢复普通课表。结构不同明确阻止对照但允许独立查看。全流程离线可用。
