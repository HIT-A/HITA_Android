# HITA 离线课表分享与好友课表管理设计

日期：2026-10-09。分支：`feat/timetable-sharing`。代码基线：`71689c9`。
状态：聊天设计及本书面设计均已由用户确认；进入实施计划阶段。未授权 commit、push 或发布。

## 1. 目标与范围

实现 PRD v1.0 的完整离线流程：A 选择个人课表生成口令，经微信/QQ 发送；B 粘贴、预览、保存、按周查看；A 再次分享后 B 确认更新。支持完整课程和仅忙闲两种模式、备注及删除。

沿用 Kotlin、Compose Material 3、Hilt、ViewModel/Repository 和 Room。不新增后端、账号关系、联网解析、实时同步、撤回、二维码或共同无课时间计算。所有新增界面文案进入 `strings.xml`。

## 2. 已核实的代码基础

- `data/model/timetable/Timetable.kt` 保存课表 ID、名称、开始/结束时间及可配置作息。
- `data/model/timetable/EventItem.kt` 保存每次事件的实际 `from/to` 时间，区分 CLASS、EXAM、OTHER、TAG；手动来源仍可为 CLASS。
- `data/source/dao/EventItemDao.kt` 支持按课表读取事件；部分个人日程查询没有课表限定，所以不能把好友事件写进 `events`。
- `data/AppDatabase.kt` 当前版本 14，保留历史 schema 和迁移链。
- `ui/main/timetable/TimetableFragment.kt` 已提供 `internal ReadOnlyTimetableWeek`，添加及长按编辑回调为空。
- `ui/timetable/detail/TimetableDetailActivity.kt` 已有导出 ICS 操作；本功能增加独立分享操作，不替换 ICS。
- `data/model/timetable/ScheduleCodec.kt` 是星期与节次的简易编码，不能承载本协议，保持原有接口。

## 3. 方案取舍

选定：在 AppDatabase 新增专用表，好友快照独立保存，使用现有只读周视图展示。

另建 Room 数据库隔离更彻底，但多一个数据库生命周期及迁移入口；同库专用表已能避免个人日程查询读取好友课程。把好友保存成普通 Timetable/EventItem 会使现有全局查询和提醒读取好友数据，不采用。

## 4. 分享快照与数据白名单

读取选定课表及其所有 CLASS 事件，在 Room 读事务中生成一致快照；不能只取当前周或只取 EAS 来源。事件没有独立单双周规则，而是实际出现日期，因此保存每个实际出现的安排，避免从星期或节次反推日期。

完整模式白名单：昵称、课表显示名称、学期显示名称、学期日期范围、时区、作息、课程显示名称、每次安排的实际开始/结束时间和地点。协议不包含本地 Timetable/EventItem/Subject ID、内部课表 code、教师、学号、账户、凭证、提醒、考试、个人活动或其他事件。

课程使用快照内连续编号关联安排，编号从 0 开始。来源 subjectId 只用于本地分组，不写入口令；没有 subjectId 时按名称分组。课程数量表示分组后的课程数，同时显示上课安排数，避免把 300 次上课误称 300 门课程。

忙闲模式在构建协议对象时就剔除课程字典、课程编号、名称及地点，不在界面层隐藏。课表显示名称改为固定的“忙闲课表”，保留昵称、学期、作息及占用起止时间；同日重叠或相邻占用合并。此模式展示占用时段数量，不宣称包含多少门课程。

空 CLASS 集合不给出可分享口令，明确提示“课表暂无可分享课程”。不以无效或过大的个人记录生成缺失课程的部分快照；整体报错。

## 5. HITA1 协议

文本结构：`HITA1:` + 无 padding 的 Base64URL(GZIP(UTF-8 紧凑 JSON))。GZIP 完整读取并验证 CRC 和结尾；编码解码不使用 Android 专属 Base64，便于纯 JVM 测试。使用已有 Gson 的 JSON 树 API，逐字段检查类型和范围，不通过宽松自动映射跳过验证。

顶层字段：

| 键 | 内容 |
| --- | --- |
| v | 整数 1，必须与前缀一致 |
| id | 随机 UUID shareId |
| n | 分享昵称，去除首尾空白，1–40 个 Unicode 码点 |
| m | `full` 或 `busy` |
| t | `[课表显示名, 学期显示名, 学期开始epochMillis, 学期结束epochMillis, "Asia/Shanghai"]` |
| p | 作息数组，每项 `[开始分钟, 结束分钟]` |
| c | 完整模式课程名称数组；忙闲模式必须不存在 |
| e | 完整模式每项 `[课程编号, 开始epochMillis, 结束epochMillis, 地点]`；忙闲模式每项 `[开始epochMillis, 结束epochMillis]` |

不写生成时间，避免内容未改变时每次分享都被视为更新。时间使用整数毫秒保留源数据，不把节次当作实际时间。字段顺序固定，课程字典与安排排序确定，以获得稳定内容摘要。地点空值规范化为空字符串。

v1 固定校园时区 Asia/Shanghai，好友日期、星期、周次及时间按该时区解释。设备系统时区变化不改变课表显示；复用组件需要支持明确的显示时区，默认值保持个人课表行为。周一作为周起点，第一周从学期开始所在周的周一计算，初始显示学期内当前周，否则第一周。前后切换限制于学期范围；使用日历日期运算，不依赖设备时区下的固定毫秒差。

手动课表学期名称从开始日期推导：1–7 月为当年春季，8–12 月为当年秋季；有可解析教务学期信息时优先使用其显示名称。名称展示不直接发送内部 code。学期日期必须有序且跨度不超过 370 天。时间范围为 2000-01-01 至 2100-01-01（不含），安排结束必须晚于开始、单次不超过 24 小时，且落在学期首日到末日的完整自然日范围内。

初始上限：整段粘贴文本 131072 字符；单个口令 65536 字符（含前缀）；解压输出 1048576 字节；课程字典 512 项；安排 4096 项；作息 48 项；课表名和学期名各 80 个 Unicode 码点；课程名和地点各 120 个 Unicode 码点。作息分钟范围 0–1440、开始小于结束，作息依次有序且不重叠。数组长度、编号引用、整数类型、字符串类型、空列表、重复 JSON 键和未知字段严格验证。源数据超限时拒绝生成，不截断。

解压采用带输出计数的流式读取，达到上限立即停止，不先解压后检查。后台线程执行编解码及数据库操作。统一返回可展示的错误类别：无口令、多个口令、版本不支持、口令过长、编码损坏、解压超限、字段非法、没有课程。禁止把原始口令或解码内容写入日志。

识别完整聊天消息中的 `HITA<数字>:` 候选，Base64URL 字符串以空白或标点结束。一个候选才解析；多个候选要求用户单独粘贴，不默默选取。未知版本显式提示更新应用；损坏字符及截断口令整体失败。后续协议版本新增独立 decoder，保留 v1 decoder 和固定测试样本。

## 6. 持久化及迁移

AppDatabase 升级 14 → 15，只新增以下表和索引，不修改、删除或复制已有个人表：

- `timetable_share_identity`：`timetableId`、`termKey` 组成主键；`shareId` 唯一。termKey 使用已解析的教务学期标识，否则采用开始日期推导的年及春/秋季。生成一次随机 UUID 后持久保存；同课表同学期复用，换学期使用新标识。编辑昵称、模式、名称、作息或同学期内调整开始日期不重置标识。跨春/秋季的学期修改视为新学期。
- `friend_timetable`：`shareId` 主键，昵称、可空本地备注、学期显示信息、模式、规范化 snapshot JSON、SHA-256 内容摘要、首次导入时间及最近更新时间。快照存一行避免替换半套课程；JSON 必须是完整验证后的规范化数据。

identity 创建采用 insert-ignore 后读取，避免同时生成两份标识。好友 DAO 不提供写入个人 events/subject/timetable 的能力。使用独立 `TimetableSharingRepository` 和 `FriendTimetableRepository`，好友管理只注入好友 DAO。

迁移注册进现有链并导出 v15 schema。14 → 15 必须走显式迁移，不能依赖 destructive fallback。设备迁移测试验证原有 Timetable、Subject 和 EventItem 记录保持不变，随后好友表可读写。

## 7. 导入与更新状态机

粘贴 → 解析及校验 → 查询 shareId → 展示预览，解析阶段零数据库写入。

- 无现有条目：提示保存新课表。
- 相同 shareId 且摘要相同：提示已导入，支持打开原条目，不重复写入、不更改更新时间。
- 相同 shareId 且内容不同：预览注明将更新既有条目，显示现有本地备注，等待用户确认。

摘要包含昵称、模式、所有白名单内容，不含本地备注和导入时间；以规范化 JSON 字节计算 SHA-256，原始压缩字节差异不算内容变化。旧口令和新口令没有可信版本顺序，MVP 不自动判断新旧，更新弹窗说明会替换本地快照。

保存事务再次比较本地状态。若预览后条目发生变化或被删除，重新预览并要求确认，不覆盖用户未确认的状态。通过预览时的摘要作为预期值进行比较；保存新条目时要求 shareId 仍不存在。更新读取当前备注并保留，保留首次导入时间，更新最近更新时间。失败不产生部分快照。删除需确认，只删除好友条目；重新导入已删除的 shareId 会成为新条目。

## 8. 界面与只读行为

- 个人课表详情增加“分享课表”，进入分享页；初始选择当前课表，可切换个人课表。
- 分享页显示名称、学期、课程数及安排数；昵称默认“好友”，完整模式默认选中。生成后弹窗提供复制和 Android ACTION_SEND 的 text/plain 系统分享。修改选择、昵称或模式后旧口令失效，重新生成；生成期间禁用重复操作。
- 课表管理增加“好友课表”独立入口，列表显示备注优先的名称、学期和更新时间，提供导入、修改备注及确认删除。备注去除首尾空白，最多 40 个 Unicode 码点；清空备注恢复昵称显示。
- 导入允许多行粘贴，预览显示昵称、学期、模式、课程/占用内容及保存或更新操作；失败在输入区域显示可理解的错误。
- 好友详情通过 `ReadOnlyTimetableWeek` 展示，点击课程只打开本页的详情弹窗，不调用个人 EventsUtils 编辑路径；忙闲仅显示“忙碌”和时间。好友事件仅在内存中适配为 EventItem，不持久化到个人表、不传递给个人提醒、今日事件、Agent 查询或个人课表 ViewModel。
- 初版复用现有 HitaTheme 与 Material 3，无新增视觉系统。空列表、加载、失败与成功状态明确。

## 9. 自动化验证与产品验收

纯 JVM 测试覆盖固定协议样本与编解码往返、单双周实际出现日期、不连续周次、临时调课、不同教室、自定义作息及异地设备时区、手动 CLASS 纳入、EXAM/OTHER/TAG 排除、忙闲解压后无课程详情、稳定排序及摘要、同学期标识复用和跨学期标识变化。

异常测试覆盖空输入/空课表、完整消息提取、多候选、未知版本、非法 Base64URL、损坏 GZIP/CRC、长度边界、解压炸弹、未知/缺失/重复字段、错误类型、非法索引、时间反转及越界、数量边界。失败路径不得写好友或个人数据库。

Room 设备测试覆盖新建、重复不写、确认更新保留备注、预览与保存之间的数据竞争、备注及删除、14 → 15 数据保留及好友数据不进入个人查询。设备测试依赖可用设备或模拟器，缺少设备时明确报告未运行，不把 JVM 测试当作迁移或设备验收通过。

运行 JVM 单测、repository hygiene 和 assembleDebug；用三校区及手动课表的实际安排数据统计口令字符数、压缩比与最坏情况，不把理论估算写成已验证结果。典型数据超过初始上限时先评估并调整上限与测试，不能默默丢课程。

真实验收使用两台设备：A 分享 → 微信发送 → B 从整段消息复制 → 断网导入 → 按周查看 → A 修改后再次分享 → B 确认更新；再验证忙闲、重复导入、备注保留及删除不影响个人课表。没有设备或真实数据时保留为明确的验收缺口。
