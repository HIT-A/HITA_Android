# 统一待办与 GeniusTA 导入

## 用户可见行为

待办页只有一个滚动列表。个人、Grader 与 GeniusTA 采用相同卡片、按真实截止时间升序、无日期置底；仍可按日期标记分隔。导入卡片显示平台、课程和截止时间。平台已提交或已过截止时间的项从待办及已完成两处排除；个人待办不受此过滤影响。「已完成」默认收起，只包含手动完成项，可恢复到主列表。既有个人待办添加、编辑、删除及日期／时分操作保留，固定文案统一为「待办」。输入框下方两个平台控件在空间足够时同排等宽，提供登录、刷新、退出和必要的错误操作，不放说明性小字。

平台刷新失败时，该平台框只显示单行「重新登录」。点击直接打开账号密码输入窗口，不先刷新。Grader 后续通过学校官方认证页提交，验证码和多因子认证由用户完成；GeniusTA 使用站点官方认证接口。

用户主动勾选后，只有平台身份核验成功才保存账号密码。再次打开该平台的登录窗口时，已保存凭据自动填充并尝试提交一次，失败后留在可手动输入的界面。手动退出断开本地连接但保留加密会话和凭据，页面不再显示该账号的数据，也不会自动重连。需要时可主动忘记本机密码。

## 方案与边界

- 背景：待办内容透明。首页容器与独立待办入口复用同一绘制规则；支持全部主题与亮暗模式。重复实现待办页背景会导致主题继续漂移。
- 列表：在展示前投影三种来源为统一行；保留各平台的登录与存储，不把远端项复制为个人记录。Grader 保留深圳教务可见性、既有账号完成标记及首页摘要契约。GeniusTA 使用独立账号，不依赖教务连接。导入截止显示北京时间，与个人截止按绝对时间排序，按设备本地日期分组。
- 登录状态：两平台优先读取已连接的加密会话。GeniusTA 会话失效且账号与保存的凭据匹配时，可在待办数据加载协程中自动尝试一次账号密码恢复；断开的账号不会走这条路径。Grader 的账号密码提交依赖官方认证页面，在显式打开登录时自动执行，不在后台绕过认证。所有凭据仅存本机加密偏好，不参与备份和迁移，不与教务或另一平台共享。完成状态按平台账号及条目 ID 隔离。
- `GET /api/v1/courses` 和 `GET /api/v1/courses/{course_id}/assignments` 返回课程和所属学生的提交状态。截止优先使用所在分组的覆盖，其次使用适用的未分组设置或课程默认日期；以带时区的时间解析。仅导入已发布、有截止且尚未提交的条目。无提交状态不当作未提交；远端已有提交但要求更新，不当作未提交。
- 不改变首页摘要覆盖来源，不改 Room 或 README 版本。不提交、修改平台课程或作业数据。诊断版 `3.2.2` 构建、单测和包清单核验后本地交付；不运行模拟器、不合并、不推送。
- 平台控件采用 Google Material Icons Round 的 [Refresh](https://github.com/google/material-design-icons/blob/master/src/navigation/refresh/materialiconsround/24px.svg) 与 [Logout](https://github.com/google/material-design-icons/blob/master/src/action/logout/materialiconsround/24px.svg)，以 Apache-2.0 许可转换为本地矢量资源。可见图形为 18 dp，保留 Material 点击区域。

## 验证

官方登录、身份、课程和作业读取实测 HTTP 200。应用式登录请求不带同源标头返回 403；带本站 `Origin` 和登录页 `Referer` 成功。读取只提供 Cookie 或只提供会话头均为 401。真实样本包含已提交记录；未提交、过期、分组覆盖及恢复用合成响应和 JVM 单测覆盖。主题视觉留待真机确认。

Windows 全量单测覆盖已有的校园卡损坏缓存恢复用例。两处校园卡存储改用同目录原子替换，解决 `File.renameTo()` 在目标文件已存在时失败的问题，不改缓存格式或回归断言。
