# 今日页信息层级与明日准备设计

日期：2026-11-16
分支：`feat/ios-parity-migration`
Android 基线：`6cc56601`
状态：设计方案；本次仅交付文档，尚未实现。

## 1. 目标与参考

打开今日页后，无需展开顶部卡片，就能回答三个问题：现在有什么安排、接下来去哪、今天还有什么紧急事项。晚间当天安排结束后，可以直接查看明天第一项安排。

本方案基于 iOS 源码实际读取结果，而非只根据公开截图推断。参考仓库为 `HIT-A/HITA-Aura`，固定提交 `26b06d0375d50b436fdd8a1557293654a67f8e67`：

| iOS 参考 | 已有行为 | Android 取舍 |
|---|---|---|
| `HITAAura/Views/Today/TodayHomeView.swift`，`scheduleSection` | 默认第一条未结束课程，“全部 N 节”展开全部；当天结束显示完成卡片 | 默认显示所有进行中的安排及下一组即将开始的安排，保留个人日程和考试，不只显示课程 |
| `HITAAura/Application/Today/TodaySchedulePresentationModels.swift`，`TodayHeroGreetingResolver` | 结合当日考试、作业截止与当前课程生成问候 | 保留考试、作业摘要；当前和下一项安排独立展示，不被问候覆盖 |
| 同文件，`TodayStatusCardResolver` | 饭点等问候参考课程作息 | 按当前课表作息推导，缺失或多表作息不一致时使用普通时段问候 |
| `HITAAura/Application/Today/TodayTomorrowPreparation.swift` | 20:30 后且今日课程全部结束，读取明日第一节课 | 采用同一时间门槛，但检查全部可见日程；仍有个人日程或考试时不提前切走 |
| `TodayHomeView.swift`，`discoveryCards` | 聚合资讯、考试、作业、收藏资源、Agent | 首期仅文字摘要，第二期先做考试和作业卡片，再补资源和资讯 |
| `TodayHomeView.swift`，`courseLocationCapsule` | 地点独立强调，可进入地图或详情 | 强调地点，点击进入现有详情；沿用此前范围，不新增校园地图 |

关联背景：[iOS 对齐主设计](2026-11-15-ios-parity-migration-design.md)、[教务版本与个人偏好约定](2026-11-16-timetable-versions-and-source-diff-design.md)。这是后续专题设计，不将全部扩展项视为原迁移清单已实现的内容。

## 2. Android 现状与问题

- `FragmentTimeLine.kt` 默认折叠顶部卡片，下一项倒计时、考试倒计时和后续列表位于展开区域。
- 顶部使用较大图标或课程进度百分比；剩余分钟、时间、地点更适合日常快速查看。
- 今日列表包含全部日程，已结束条目虽然简化，但仍占据列表前部。
- `buildHeaderState` 中固定早安、饭点判断排在即将上课之前，可能掩盖临近安排。
- `weekEventsLiveData` 实际查询后续四项，不能将它作为完整本周或明日数据来源。
- 今日页尚未聚合作业摘要；加载未完成与真实空列表需要明确区分。

## 3. 分期与范围

| 阶段 | 范围 | 交付边界 |
|---|---|---|
| 第一期：核心信息 | 顶部状态、今日重点文字摘要、接下来/全部安排、明日准备、状态区分 | 使用现有本地数据；不新增网络服务和数据库表 |
| 第二期 A：摘要卡片 | 考试、作业两张紧凑卡片，点击进入已有详情或列表 | 明确数据来源、账号范围与失败状态；不另建同步任务 |
| 第二期 B：扩展摘要 | 资源与资讯预览；按需要补 Agent 入口 | 使用已有来源与路由，避免重复入口和大量卡片挤占日程 |

天气、定位和校园地图继续暂缓；不照搬 iOS 平台材质。复用 Android 现有主题、壁纸、字号与无障碍规范。第二期卡片不作为第一期完成条件。

## 4. 页面结构

默认从上到下：

1. 现有日期与周次标题；继续使用主界面的课表显示目标。
2. 紧凑状态区：问候、当前安排或下一项倒计时、今日重点摘要。
3. “接下来 · 全部 N 项”：进行中的安排和下一组安排卡片。
4. 当天结束状态；满足晚间条件时加入明日准备。
5. 第二期的考试、作业等摘要卡片。

不为图片或装饰预留固定大面积。课程卡片和顶部状态重复的信息保持简洁：顶部给出状态和剩余时间，卡片给出完整时间、节次、地点及详情入口。

### 4.1 顶部状态与今日重点

- 始终可见当前/下一项状态，不再要求展开顶部卡片。
- 进行中显示“正在上课/考试/进行中”和“距结束 N 分钟”；下一项显示“距开始 N 分钟”。课程进度条可保留，百分比不作为主要文案。
- 临近开始阈值沿用 15 分钟；普通问候不能遮住临近安排。
- 有多个同时进行或同刻开始的安排时，显示冲突数量，列表保留全部对应卡片；不随意取其中一条作为唯一安排。
- 今日重点优先提示尚未结束的当日考试，再提示今日尚未完成且未过期的截止作业。过期作业另标“逾期”，不能伪装成即将截止；已完成作业不计数。
- 已结束的考试不继续提示为待参加。缺少可靠时间的考试不编造倒计时，显示日期/待核对时间。
- 本地手写作业和 Grader 继续保持来源身份；不按相同标题猜测为同一项。计数只包含当前可用来源，未知或失败来源不显示为零。
- 姓名是否显示遵循现有身份可见性偏好；不为了问候新增身份信息持久化。

示例：“今天还有 1 门考试 · 2 项作业今晚截止”；下一行“距上课 12 分钟”。实际文案统一放入 `strings.xml`。

### 4.2 接下来与全部安排

- 时间状态统一使用同一个 `now`：`start <= now < end` 为进行中，`end <= now` 为已结束，其他为未开始。
- 默认显示所有进行中的安排，以及开始时间最早的下一组安排；当下一组有多项同刻开始时全部展示。
- “全部 N 项”展开今天全部真实日程，按开始时间、结束时间、稳定 ID 排序，含已结束条目；展开后可点击“收起”。已结束条目弱化，但保留时间和详情入口。
- N 是今日可见真实日程数，不包含引导提示卡。使用“项”而非“节”，避免把考试、个人日程都称为课程。
- 空档文案给出下一项时间；当天全部结束则显示“今天的安排已结束”。不将课程结束等同于所有作业已完成。
- 日程卡片突出名称、起止时间、适用时的节次和地点。点击进入现有详情；地点不明时明确标记，不生成导航地址。
- 保留现有 mini 课程条，通过一致的时间规则避免与今日页出现不同的当前课程判断。
- 分钟更新、资料刷新、切换 Tab 不重置滚动位置或自动收起列表。跨日重置为默认接下来模式；切换显示目标后恢复该目标的合理初始位置，避免遗留另一课表的内容。

### 4.3 明日准备

- 当地时间到达 20:30，且今日全部可见真实日程已结束时出现。
- 查询明天完整日期范围内的安排，显示日期、最早开始的一组安排及地点。同刻多项标出冲突，不隐去其他项。
- 查询跟随当前单课表或组合显示目标，尊重隐藏、删除与最新采纳结果，不受用户正在浏览哪一周影响。
- 今日没有日程时仍须达到晚间门槛；明日确认没有日程才显示“明天暂无安排”。数据未就绪不显示为空。
- 午夜自然切换到新一天；覆盖周日到周一、跨月、跨年。今日与明日使用同一明确日期边界，避免遗漏或重复跨午夜日程。
- 有未完成作业不会阻止明日安排展示；截止或逾期提醒继续保留。

### 4.4 数据状态与失败处理

| 状态 | 展示与操作 |
|---|---|
| 显示目标正在解析/本地数据加载中 | 稳定占位，不先显示“今天没课” |
| 没有课表显示目标 | 提供选择或导入入口；不承诺教务一定有课程 |
| 数据已就绪，今天没有安排 | 展示真实空状态，晚间按条件展示明日准备 |
| 已有本地数据，但在线更新失败 | 继续显示本地内容；仅在现有同步状态能证明失败时提示重试，不凭缓存猜测登录失效 |
| 已确认会话失效 | 提供已有登录入口；本地课程仍可查看 |
| 某摘要来源失败/未登录 | 只在该摘要提示状态，不遮住整个今日页，不把未知计为零 |

同步时间只有已有可信记录时才展示，不以页面刷新时间冒充最后成功同步时间。不同来源的加载和错误互不覆盖。

## 5. 数据与实现路径

### 5.1 现有组件

| 文件/模块 | 拟调整职责 |
|---|---|
| `ui/main/timeline/FragmentTimeLine.kt` | 拆分顶部状态、接下来、空状态和明日准备组件；减少单文件展示逻辑 |
| `ui/main/timeline/FragmentTimelineViewModel.kt` | 协调当前目标、今日/明日查询、考试与作业状态；输出显式加载/内容/错误状态 |
| `ui/main/timeline/TimelineListProjection.kt` | 扩展纯函数投影，统一排序、时间状态、默认可见集合及统计 |
| `data/repository/DisplayScopeResolver.kt`、`TimetableRepository.kt` | 复用当前显示目标和日期范围查询；需要时最小补充只读状态，不建立平行数据源 |
| `data/repository/homework/`、现有 Grader 数据层 | 复用作业状态与期限规则，保留已完成、来源和账号隔离 |
| `ui/main/MiniCourseResolver.kt` | 核对并共享时间边界规则；不为此次布局改动重写 mini 条 |
| `app/src/main/res/values/strings.xml` | 新增状态、计数、剩余时间、明日准备与无障碍文案 |

新增文件限于职责清楚的今日展示模型、纯投影与 Compose 组件；最终命名在实现时确定。第二期摘要由 Repository 提供数据，不从另一个页面的 ViewModel 抓取状态。

### 5.2 数据约束

- 继续走 Room/现有仓库 → ViewModel → Compose。课程、考试和个人日程的查询与隐藏规则沿用当前显示投影。
- 首页只读，不改变教务 metadata，不创建教务版本，不修改个人偏好；点击详情后的写操作仍走既有授权与统一写入口。
- 本地手写作业按现有本地日期/时间规则解析，旧日期无时间按 23:59；Grader 沿用自身时间解析。课程日期沿用现有课表规则，不能用某一来源的时区规则覆盖其他来源。
- 查询使用明确清零的日期边界；与窗口相交的跨午夜日程按现有规则展示，进行中状态不得因零点被截断。空/错误状态不得由 `emptyList()` 单独推断。
- 时钟只在页面真正可见时运行，按显示精度更新；切到前台、日期或时区变化立即重新派生。所有派生使用同一注入时刻，避免同一帧内判断不一致。
- 不新增每分钟联网行为，不新增 WorkManager/AlarmManager 任务。首页与作业页共享现有刷新协调，不能重复触发 Grader 登录或抓取。
- 初期不新增 Room 表、版本号、权限或偏好开关。若实现发现必须持久化新状态，先单独评审，不默默扩大范围。

## 6. 实现与提交顺序

1. 纯投影与读取状态：今日/明日、进行中与下一组、摘要计数、边界测试。
2. 今日界面：顶部状态、全部安排切换、明日准备、加载/失败状态及滚动保持。
3. 真机验收与文档记录；第一期通过后按功能分类提交。
4. 第二期 A 单独实现和提交考试、作业卡片，再评估第二期 B。

沿用仓库已更新的约定：功能完成并 Review、本地验证通过后提交；Push 需独立授权。本次文档推送不等于授权全部实现，也不等于授权未来功能提交后的推送。

## 7. 验证与验收

### 纯逻辑测试

- 上课前 15 分钟、开始瞬间、结束瞬间、长于一小时的剩余时间与同时发生的冲突。
- 无日程、只有个人日程、只有考试、隐藏课程、组合课表、目标解析中和加载失败。
- 20:29/20:30、晚间仍有日程、当日全部结束、明日无日程、明日同时多项。
- 午夜、周日到周一、跨月跨年、跨午夜日程和时区变化。
- 作业已完成/今日截止/逾期/无日期/无时间、考试已结束或时间不完整、来源未知或失败、账号切换。

### 界面与设备验收

- 默认首屏可读到当前或下一项状态、时间和地点，无需展开顶部卡片。
- 展开/收起、点击详情、登录/重试路由正确；分钟刷新和切 Tab 保留滚动位置。
- 经典、玻璃、波普等现有主题，浅色/深色、壁纸、长课程名、大字体和窄屏可用；计数与详情支持无障碍阅读。
- 真机检查跨日刷新、前后台恢复、与 mini 条状态一致；仅刷新今日页不得产生教务版本或修改隐藏状态。
- 运行相关 JVM/插桩测试、`./gradlew assembleDebug`、仓库检查和 `git diff --check`。设备安装使用 `adb install -r`，不清空数据。
- 模拟数据、合成界面与真实教务服务分别记录证据。没有在线验证时，不宣称登录、真实同步或上游通知已经通过。
